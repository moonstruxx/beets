# Project Guardrails

> Auto-generated by `/make-guardrails`. Regenerate with the same command when
> architecture or conventions change.

## Architecture Constraints

- Respect the layer order: `beets/util` ← `beets/dbcore` ← `beets/library` ←
  (`importer`, `autotag`, `ui`), with `beets/plugins.py` and
  `beets/metadata_plugins.py` as the extension contract. `beets/dbcore/*` must
  never import `beets.library` (it may import `beets`, `beets.util`,
  `beets.context`); `beets/library` may import `dbcore`, never `ui`/`importer`.
  `beets/util` may import `beets.library` only under `if TYPE_CHECKING`.
- `beets/dbcore` must stay free of music-domain concepts. Album/Item specifics
  belong in `beets/library` (`models.py`, `fields.py`).
- Plugins extend behaviour through the event bus (`beets/events.py` +
  `plugins.send`) and the `BeetsPlugin` API — not by monkeypatching core, not by
  editing `beets/ui` to special-case a plugin.
- Every event an agent adds or consumes must be declared in `beets/events.py`
  (a `Literal` name in the `EventType` union, a payload `TypedDict`, and an
  overload of `plugins.send`/`register_listener`).
- A new metadata source must subclass `beets.metadata_plugins.MetadataSourcePlugin`
  (or `SearchApiMetadataSourcePlugin`) and implement `album_for_id`,
  `track_for_id`/`candidates`; do not add another `data_source`-only
  `BeetsPlugin` — that shim is deprecated and removed in v3.0.0.
- New CLI commands live in `beets/ui/commands/<name>.py` and are registered via
  a `Subcommand`; don't grow `beets/ui/__init__.py` with command logic.
- New bundled plugins live at `beetsplug/<plugin_name>.py` (or a package with a
  matching name); the module name, `BeetsPlugin.name`, and the config section
  name are the same string.
- Path and artwork locations are computed through `functemplate` + `pathformats`
  + `Library` path formats; never build library paths with ad-hoc string
  concatenation.

## Naming Conventions

- Commit subjects are `<area>: <imperative summary> (#PR)` where `<area>` is the
  touched subsystem, e.g. `convert: skip missing album art instead of crashing
  (#6749)`, `importer: expose the shown candidate ... (#7162)`.
- Migration classes are named `<What>Migration` in `beets/library/migrations.py`
  (the recorded name is derived from the class name, minus the suffix, snake_cased).
- Field types are `<Name>Type` in `beets/dbcore/types.py` (`PathType`, `DateType`,
  `DurationType`); null-flavoured variants are prefixed `Null`.
- Import stage functions are verbs in `beets/importer/stages.py`
  (`read_tasks`, `group_albums`, `lookup_candidates`, `user_query`,
  `manipulate_files`).
- Tests mirror the source path: code in `beets/util/x.py` → `test/util/test_x.py`;
  plugins → `test/plugins/test_<plugin>.py`.

## Code Style

- Format and lint with ruff through poe — never by hand:
  `poe format`, `poe check-format`, `poe lint`. Config lives in
  `pyproject.toml` (`target-version = "py310"`, `line-length = 80`,
  `skip-magic-trailing-comma`).
- Keep lines ≤ 80 characters (ruff `max-line-length = 88` only for the
  pycodestyle check; the formatter is 80).
- Start modules with `from __future__ import annotations` and annotate public
  functions; the package ships `py.typed`, and `beetsplug.musicbrainz`,
  `beetsplug.mbpseudo`, `beetsplug._utils`, `beetsplug.tidal.*` are checked with
  `mypy --strict`.
- Import order is enforced by ruff isort (`split-on-trailing-comma = false`);
  put type-only imports under `if TYPE_CHECKING` (ruff `TC` rules are enabled).
- Do not silence rules or add `# noqa` to get green CI; fix the code or raise the
  cost in config with justification.
- RST docs and the changelog must pass `poe format-docs` (docstrfmt) and
  `poe lint-docs` (sphinx-lint, all checks, plus the "use double backticks for
  inline literals" rule).
- Comments explain non-obvious reasons and invariants only; keep AI-written
  comments concise (see `AI_POLICY.md`).

## Testing

- Every behavioural change needs a pytest test under `test/` in the mirrored
  location; bug fixes should include a test that fails before the fix.
- Use `poe test` (`uv run pytest -p no:cov`); pass pytest options through it,
  e.g. `poe test --lf`. Use `poe test-with-coverage` when coverage matters.
- Never make network calls in tests: use `responses` / `requests-mock`. The
  plugin conftest patches the rate-limiting session so mocked requests aren't
  throttled.
- Build test data with the existing helpers (`beets/test/helper.py` `TestHelper`,
  `test/conftest.py` fixtures, `test/rsrc/` media) instead of inventing new
  fixture machinery.
- Tests must pass with `pytest-randomly` shuffling and `-n auto --dist=loadscope`;
  don't rely on execution order or cross-test shared state.
- Keep tests out of the working tree's caches: pytest config already redirects
  caches to `/tmp` and reports to `.reports/`.
- Code that shells out to external tools (ffmpeg, fpcalc, mp3gain, gstreamer)
  belongs behind the weekly `INTEGRATION_TEST=1` tier, not the default suite.

## Build & Deployment

- Use uv for everything: `uv sync` (or `poe install`), `uv run pytest`,
  `uv build`. Do not introduce pip/poetry/conda instructions.
- Use poe for tasks — `poe` alone lists them. CI calls `poe install`,
  `poe test`, `poe lint`, `poe check-types`, `poe docs`, `poe lint-docs`.
- Supported interpreters are Python 3.11–3.15 (`requires-python = ">=3.11,<3.16"`);
  don't add syntax or stdlib APIs that require a narrower range.
- CI gates that must be green: `lint.yaml` (format, lint, mypy, docs) on changed
  files, `ci.yaml` test matrix (Ubuntu + Windows × 3.11–3.15) including the
  base-install job, and the changelog reminder.
- Optional/heavy features are extras in `[project.optional-dependencies]`; the
  core dependency list must stay small. Non-Python requirements are documented
  as inline comments next to the extra.
- Never hand-edit `uv.lock`; change `pyproject.toml` and regenerate with uv.

## Data & State

- Adding a field to `Item`/`Album._fields` auto-creates a SQLite column at open
  time (`ALTER TABLE ADD COLUMN`) — that alone needs no migration.
- Changing *existing data* (rename/split/relocate values) requires a
  `dbcore.Migration` subclass in `beets/library/migrations.py`, registered in
  `Library._migrations`, chunked (`CHUNK_SIZE = 1000`), idempotent, and safe to
  re-run; completion is recorded in the `migrations` table.
- `create_backup_before_migrations` is on by default — never remove the backup
  path or write to a user database outside `Database`/`Transaction`.
- Paths and `artpath` are stored as bytes (`PathType`); convert only at display
  or filesystem boundaries (`util.displayable_path`, `util.syspath`).
- Album-level fields are denormalized onto items: when changing album store/load
  semantics, verify items are updated consistently (the absolute-`artpath`
  regression and its migration are the precedent).
- Import decisions must go through `Action`/`DuplicateAction`; don't invent
  parallel decision state in plugin code.
- Resume/incremental behaviour is owned by `ImportState` (`state.pickle`);
  changes there must keep `--resume` and `--incremental` correct.

## Security

- `AI_POLICY.md`: agents may interact with this repository **only for code
  review** — do not create PRs, open issues, or post comments as a contributor;
  disclose AI assistance in any contribution; never answer maintainers on a
  contributor's behalf.
- Never commit credentials, tokens, or API keys. Service credentials belong in
  the user's config (`config.yaml` subview) or plugin token files, never in code,
  tests, fixtures, or logs.
- The `web` and `aura` plugins have **no authentication**; keep them bound to
  localhost and don't build features that assume they are secured.
- Keep user input flowing as bound parameters through `dbcore` queries; never
  format user strings into SQL.
- Archive extraction and file moves must stay inside the configured library
  directory; preserve the existing traversal guards in `ArchiveImportTask` and
  the move/copy conflict checks.

## Dependencies

- Package manager: **uv** with a committed `uv.lock`. Build backend: **hatchling**.
- Prefer the standard library or an existing core dependency over adding a new
  one; justify every new core dependency by what cannot be done without it.
- Plugin-only dependencies go in the plugin's extra and are imported lazily
  inside the plugin module/function so core imports never fail.
- Use `requests` with the shared session helpers in `beetsplug/_utils/requests.py`
  (retries + rate limiting) rather than raw `requests.get`.
- Respect the configured rate limits (MusicBrainz default 1 req/s via
  `musicbrainz.ratelimit` / `ratelimit_interval`); never bypass or disable the
  limiter to speed up imports.

## Git Workflow

- Every user-visible change adds an entry to `docs/changelog.rst` **in the same
  PR**, under the appropriate Unreleased section, using `:bug:`/`:user:` roles
  and the issue reference. A workflow comments on PRs that skip this.
- PRs use `.github/pull_request_template.md` and tick/scratch its checkboxes
  (changelog, docs, tests) as appropriate.
- Branch → merge commit on `master`; don't rewrite published history on `master`.
- Contributions follow `CONTRIBUTING.rst` (discuss before large changes; tests
  and docs expected).
- Do not create commits, push, or open PRs unless the user explicitly asks.
